## Rendering risks and design recommendations

These are source-supported risks/recommendations, **not claimed browser reproductions**:

- **Narrow action rows:** [TasksLayout:21](../src/features/tasks/components/TasksLayout.vue#L21) keeps title/date/save in a nonwrapping flex row with intrinsic form-control minimum widths. Care-team addition also keeps multiple controls on one row. At 320/375px, zoom and long Arabic strings, inspect clipping concealed by global `body { overflow-x:hidden }`; use shrinkable, wrapping/stacked owned action groups.
- **Visit column stretch:** global/scoped `.visit-layout` changes to column while retaining `align-items:flex-start`; `.visit-card-main` has no full-width/stretch rule. Short/intrinsically narrow content can leave an underfilled card. Explicitly stretch column children while retaining desktop sidebar alignment.
- **Sticky clinical context:** patient detail mixes document scrolling with `.patient-scrollable-content { overflow-y:auto }` and unbounded `height:100%`; sticky context should follow a deliberate scroll owner. Check long pages and short landscape viewports before changing overflow. Sticky positioning depends on its nearest scroll container, per [CSS Positioned Layout](https://www.w3.org/TR/css-position-3/#sticky-pos).

Recommended ownership: shell controls chrome/viewport/gutters/banner space; PageContainer controls route width/status; page layouts control content grids; widgets control their own scrolling. Keep one primary document scroll owner and explicit table/dropdown scroll regions.

Short account/password/appointment forms currently inherit FormWrapper's 1400px `lg` default. Use the existing form/small width for short forms and standard/wide for dense clinical pages. The `standard/wide/form` PageContainer options currently have no explicit route consumers; adopt intentionally rather than adding competing max-width CSS. Prefer named page containers to broad `.app-main > :not(.footer)` rules. Consolidate duplicated global/scoped visit/sidebar geometry by ownership; do not merge unrelated CSS merely to reduce files. Give route changes a deliberate main-focus policy, consistent page headings and one transitionable route root.
