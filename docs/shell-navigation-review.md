## Responsive risks matching the sideways-scroll symptom

These are source-supported risks, **not confirmed browser reproductions**:

- **Arrival-driven width changes:** notification badge is an ordinary flex child inside the bell button; icon-only controls have a minimum width but no fixed footprint/count cap. New/long counts widen the button and the nonshrinking topbar action group. Bottom-nav badge is a third vertical child inside a fixed 60px bar; items lack equal flexible tracks and bounded labels. Reserve stable button/item geometry, position/cap badges outside text flow, and verify 0→1→99→100 counts at narrow widths/text zoom.
- **Hidden scrollable overflow:** `base/reset.css:30` globally sets body `overflow-x:hidden`. This can conceal overflow while focus/scroll APIs still move scrollable ancestors. Do not treat another global hide rule as the fix; find the overflowing element and bound/wrap it. Keep intentional table/tab scrolling local. Compare both physical edges in RTL; negative `left` is as relevant as excessive `right`.
- **Panel opening/content changes:** panels mount before post-tick positioning; asynchronous content and width-limit changes can alter bounds between measurements. Check first frame as well as steady state, both directions, keyboard/zoom, and short landscape screens. Native select popups need separate browser checks; they are not managed by the floating-position composable.

Fluidity improvements: mobile drawer currently animates width, then becomes immediately `visibility:hidden` on close, so the closing animation disappears and opening squeezes contents. Prefer a fixed-width directional transform with visibility/pointer/focus lifecycle kept consistent. Keep drawer brand/close control anchored while only the long link region scrolls. `page-fade` transition names have no corresponding CSS states; define a deliberate route transition/fallback and honor reduced motion, including explicitly requested smooth scrolling.
